# Research bot: source and evaluation opportunities

Research date: 2026-10-05. Scope: primary-source verification plus README/package inspection; recommendations, not deployed functionality. No secrets, paid purchases, live sends, or production changes.

## Highest-value opportunities

1. **Collect richer player evidence, not just more websites.** DartsOrakel's public player statistics page includes first-nine/first-three averages, averages with/against throw, legs won throwing first/second, 140s, and functional doubles. These are candidate fields that separate scoring, finishing, and throw advantage. Availability was verified on one player's last-12-month table, not across every match/player/competition. A 12-month aggregate must not be relabeled as last-10 form; denominators, timestamps, definitions, and coverage need validation. Public access is not a commercial redistribution license. [DartsOrakel player statistics](https://dartsorakel.com/player/stats/1993/darren-beveridge).

2. **Make match format first-class.** PDC describes the World Grand Prix as double-start. This is direct evidence that pooling every tournament's average without format context can be misleading. Proposed metadata: double-in versus standard, sets versus legs, best-of length, stage/floor, round, and known throw order. Test their incremental predictive contribution; do not invent coefficients or assume all fields are available. [PDC World Grand Prix report](https://www.pdc.tv/news/2025/10/11/2025-boyle-sports-world-grand-prix-semi-finals-latest).

3. **Persist dated observations and globally coordinate ingestion.** Jina currently documents 20 Reader requests/minute without a key, 500 with a free key, and limits tracked per IP/key; token constraints also apply. README's process-local pacing is therefore not a global guarantee. Deduplicate players across fixtures, fetch once per freshness window, store validated snapshots, and use shared quotas before raising concurrency. A free key changes access/account/token terms; it is not unlimited data or a bypass of source restrictions. Verify permission and transport integrity independently. [Jina Reader](https://jina.ai/reader/).

4. **Separate collection from report delivery and add recovery.** Vercel says cron failures are not automatically retried and overlapping runs need a locking mechanism. Its Hobby cron can trigger anywhere within the scheduled hour and cannot run more than daily. Consequently the README's daily report time is not an exact delivery guarantee, and a near-start odds watcher cannot be implemented simply by adding frequent Hobby cron expressions. Proposed architecture: durable run/row state, checkpointed enrichment, resumable jobs, idempotent report delivery, failure alerts, and explicit upgrade/cost approval if frequent scheduling is required. [Vercel cron management](https://vercel.com/docs/cron-jobs/manage-cron-jobs).

5. **Require forecast validation before probabilities or value claims.** Calibration curves compare predicted probabilities with observed frequencies; Brier/log loss are proper scoring rules, but Brier score mixes calibration and discrimination. Measure both proper scores and reliability diagrams, stratified by competition/format, rather than just prediction accuracy or a good-looking confidence label. Maintain separately named data-quality confidence and estimated win probability. This is an evaluation design recommendation, not evidence this bot already has a validated model. [scikit-learn calibration](https://scikit-learn.org/stable/modules/calibration.html).

6. **Backtest as-of-time, not on today's reconstructed form.** Time-ordered splits avoid training on future data and testing on earlier data. Persist when each fixture, statistic, price, and correction was actually observed; calculate pre-match features exclusively from information available then. Darts matches are irregularly spaced, so calendar-based walk-forward windows with tournament/session grouping are more appropriate than blindly applying equal-row folds: the referenced API explicitly assumes equal spacing for comparable durations. Compare simple Elo/form baselines, richer models, and contemporaneous market baselines. [scikit-learn time-series splitting](https://scikit-learn.org/stable/modules/generated/sklearn.model_selection.TimeSeriesSplit.html).

7. **Build an odds observation ledger before shopping for feeds.** The Odds API documents point-in-time historical snapshots, paid-only historical access, and coverage beginning when each sport/bookmaker was added. This illustrates the procurement checks required, not a verified recommendation for darts: this research did not establish its darts, MODUS, or TippmixPro coverage. Existing Eredmenyek collection remains one bookmaker and on-demand per README. First archive permitted observations with bookmaker, market, selections, timestamp, scheduled start, and eventual result. For expansion, require a provider to demonstrate exact competitions, historical depth, latency, market semantics, licensing, and sustainable cost. [The Odds API historical data](https://the-odds-api.com/historical-odds-data/).

## Decision rules recommended from this evidence

- Do not promise "all useful data": use an explicit coverage matrix by source, field, competition, and date; unavailable is not zero.
- Preserve event time separately from observation time, and distinguish observed, inferred, corrected, and stale fields.
- Prioritize richer statistics and persistence before LLM upgrades. The current deterministic bot is already appropriate for calculations; explanation quality cannot manufacture missing evidence.
- Normalize two-outcome decimal prices using `qA = (1 / oddsA) / ((1 / oddsA) + (1 / oddsB))` only as a transparent proportional-margin market baseline, not as true probability. Display the overround and never combine unmatched bookmakers, timestamps, or markets.
- Treat proposed statistical features as hypotheses: retain them only if they improve held-out scores or demonstrably reduce research time/error rate.
- Technical page accessibility does not establish scraping/redistribution rights. Respect restrictions, documented quotas, and contractual terms; avoid private endpoints, CAPTCHA evasion, or proxy rotation.

## Research limitations

No fresh application collector smoke tests, full source coverage audit, permission/legal opinion, model training, or economic ROI experiment was run. PDC verification relies on its indexed official report because this research tool's direct page rendering returned no body. Source/platform limits can change and should be rechecked before implementation.
